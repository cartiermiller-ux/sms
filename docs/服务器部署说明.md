# Msm 服务器部署说明（宝塔 / 阿里云）

> 部署时间：2026-09-24
> 服务器：`120.24.175.80`（阿里云 ECS，Ubuntu 26.04.1 LTS，2 核 / 1.7G 内存 / 20G 磁盘）

---

## 一、访问地址

```
http://120.24.175.80/
```

只能走 **80 端口**（已实测云安全组只放行了 22 和 80；8888 面板和 8080 从公网都连不上）。
后端因此不对外暴露，全部经 Nginx 反代。

---

## 二、架构

```
浏览器 / App
    │  HTTP :80
    ▼
┌─────────────────────────────────────────┐
│ Nginx 1.28.3                            │
│  /            → /www/wwwroot/msm/h5     │  静态 H5
│  /api/        → 127.0.0.1:8080/         │  后端接口（去掉 /api 前缀）
│  /api/ws      → 127.0.0.1:8080/ws       │  WebSocket（带 Upgrade 头、长超时）
│  /preview/    → 127.0.0.1:8080/preview/ │  上传文件预览
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ SpringBoot chat-api  127.0.0.1:8080     │  systemd: msm-backend
│  profile = server                       │  JVM: -Xms128m -Xmx400m
└─────────────────────────────────────────┘
    │                    │
    ▼                    ▼
 MySQL 8.4.11        Redis 8.0.5
 127.0.0.1:3306      127.0.0.1:6379
 库 boot-im          无密码（仅本机）
```

**为什么用同源 `/api`**：云安全组不放行 8080，浏览器直连端口会失败；
改成同源反代后只有一个端口，且将来加 HTTPS 也不会出现混合内容问题。
前端 `config.js` 已统一成 `location.origin + '/api'`，本地开发由 Vite 做同样的代理。

## 五、与「用宝塔脚本装环境」的偏差（重要）

你选择的是「用宝塔官方脚本装」，实际执行时发现**宝塔的安装脚本全部是从源码编译**，
在 2 核 1.7G 的机器上不可行，因此改用了 apt 的二进制包：

| 软件 | 原计划 | 实际 | 原因 |
|---|---|---|---|
| MySQL | 宝塔脚本 | **apt** mysql-server 8.4.11 | 宝塔脚本要编译 `gcc-10.5.0` + `openssl-1.0.2u` + `boost` + `mysql-boost`，预计数小时且极易 OOM。脚本里确认**不含任何预编译二进制** |
| Nginx | 宝塔脚本 | **apt** nginx 1.28.3 | 宝塔 nginx.sh 同样从源码编译 OpenSSL 1.0.2u，编译 20 分钟仍未完成 |
| Redis | 宝塔脚本 | **apt** redis-server 8.0.5 | 同上，且与 Nginx 的安装**并发操作同一份 OpenSSL 源码树**，互相干扰 |

**影响**：宝塔面板的「软件商店」里这三个会显示为未安装，不能通过面板管理它们的启停和配置。
站点文件和 Nginx 配置仍放在宝塔惯用的 `/www/wwwroot` 下，面板的文件管理器可以正常使用。

**如果你希望它们归宝塔管理**，两条路：
1. 在面板「软件商店」里重新安装（面板会走同样的编译流程，需要等很久，且建议先卸载 apt 版本）
2. 保持现状（apt + systemd 管理，稳定且已经跑通）

## 八、内存说明

服务器只有 1.7G 内存，各服务占用大致为：

```
MySQL  ~400M     Redis ~10M     Nginx ~10M
JVM    ~450M（-Xmx400m + metaspace）
系统   ~200M
合计   ~1.1G，剩余约 400-600M
```

还有 1G swap 兜底。**不建议在这台机器上再装其他 Java 服务**。
若并发量上来，优先加内存，其次调大 `-Xmx`（改 `/etc/systemd/system/msm-backend.service`）。

## 九、更新部署（改了代码之后）

```powershell
# 本地
cd _deploy\frontend  ; npm run build:h5            # 改了前端
cd _deploy           ; .\rebuild-backend.cmd        # 改了后端

# 上传（用 _deploy\tools\ 下的 SSH 工具，或宝塔文件管理器）
#   前端: 打包 dist\build\h5 → 解压到 /www/wwwroot/msm/h5
#   后端: chat-api.jar      → /www/wwwroot/msm/backend/

# 服务器
systemctl restart msm-backend     # 后端
# 前端是静态文件，覆盖即生效
```
