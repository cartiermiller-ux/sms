## 四、页面结构

### ① 消息


- 会话列表来自 `store.chatlist`，置顶（`top==='Y'`）优先、其余按时间倒序

### 顺带搞清的一件事：uni-app H5 的存储格式

排查线上注入登录态时确认了 uni-app H5 的 storage 序列化规则：

```js
const n = typeof t
const o = ("string" === n) ? t : JSON.stringify({ type: n, data: t })
localStorage.setItem(key, o)
```

**字符串值原样存储**，只有非字符串才包 `{type, data}`。

> 另外：**生产构建里 `uni` 不是全局对象**（开发构建里是）。
> 所以自动化脚本要注入登录态，直接写 `localStorage` 比调 `uni.setStorageSync` 可靠，
> 开发/线上都通用。

## 十、Compact Density 尺寸系统（全局压一档）

### 先量后改

用 `_deploy\tools\msm-measure.mjs`（CDP 注入设备尺寸后逐元素 `getBoundingClientRect`）
量了线上真实渲染值，发现**问题和你感觉的不完全一样**：

| 项目 | 实测 | 你的 Compact 目标 | 判定 |
|---|---|---|---|
| 输入框高 | 54px | 52–56px | 本来就符合 |
| 主按钮高 | 52px | 52–56px | 本来就符合 |
| 输入框圆角 | 14px | 12–14px | 本来就符合 |
| H1 标题 | 27px | 28–32px | 本来就符合 |
| 左右边距 | 26px | 20px | 偏宽 |
| **登录页品牌头** | **160px** | — | 🔴 太厚 |
| **`.auth__form` flexGrow** | **1** | 0 | 🔴 **元凶** |
| **消息页头部** | **169px** | — | 🔴 太厚 |
| 空状态（含 96px logo） | **354px** | — | 🔴 太大 |
| 消息页搜索框 / 分段 | 40 / 43px | ~36 | 偏大 |
| 快速入口 | 107px | — | 偏高 |

**真正的原因不是"每个控件都大"，而是：**
1. `.auth__form { flex: 1 }` 把登录内容**拉伸铺满整屏 915px** —— 观感上"到处是大间距"
2. 消息页把「品牌区 + 搜索 + 分段」堆成 169px 的厚头
3. 空状态 96px logo + 70px 上边距 = 354px

### 改后的实测值

|---|---|---|
| 登录页品牌头 | 160px | **108px** |
| 登录页左右边距 | 26px | **20px** |
| 输入框高 / 圆角 | 54 / 14px | **52 / 12px** |
| `.auth__form` flexGrow | 1 | **0** |
| 消息页头部 | 169px | **136px** |
| 搜索框 / 分段 | 40 / 43px | **36 / 34px** |

| 会话行高 | 82px | **68px**（头像 48px） |
| 卡片圆角 | 16px | **14px** |

**登录页核心区域从"铺满 915px"压到约 620px**，落在你要的 500–600px 量级。
