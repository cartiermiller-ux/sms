### 为什么一开始算不出 SHA1

PKCS#12 里**私钥用 3DES 加密、证书用 RC2-40 加密**，没有密码无法解密。
文件里只有一段明文属性（别名 + 生成时间戳），所以能读出别名但算不出指纹。

> 密码只在 DCloud「Android云端证书」页签点开时以弹窗形式显示：
> 「您的证书密码为：<REDACTED_KEYSTORE_PW>，为了您的证书安全请不要将该密码泄露给他人！」
> 建议把这串密码抄到密码管理器里，DCloud 不一定每次都弹。

## 2. 为什么要填「各平台信息」

**不是随便填的 —— AppKey 被三方绑死。**

你在「离线打包Key管理」页签里的 AppKey：

```
appid:   __UNI__510B38E
平台:    Android
AppKey:  <REDACTED_DCLOUD_APPKEY>
```

DCloud 官方文档（[申请 · 离线打包AppKey](https://nativesupport.dcloud.net.cn/AppDocs/usesdk/appkey.html)）原文：

> appid + 应用包名 + 签名sha1 **三者必须与申请填写的信息一致**才可以的。

对不上任何一个，App 启动就报 **「未配置AppKey或配置错误」**。

所以：**「各平台信息」里填的 SHA1，必须等于最终给 APK 签名的那张证书的 SHA1。**

### 操作顺序

1. 页面 **「各平台信息」** → Android 那一行点 **「修改」**
2. 包名填 `uno.imessage.app`
3. 签名 SHA1 填 `25:5D:71:27:5F:77:53:FC:04:96:65:45:1B:F1:9E:1A:2B:5F:F7:F8`
4. 保存
5. 回到「离线打包Key管理」确认 AppKey 还是 `4dc56d...`；**如果变了，记下新值**

> 你截图里那条橙字第 2 点就是这个意思：「包名及签名信息在"各平台信息"中"修改"中配置」。

## 3. 云打包（推荐路径，最省事）

用 DCloud 云端证书的话，**云打包时 DCloud 自动用它签名**，你什么都不用传。

1. HBuilderX → **文件 → 打开目录** → 选 `_deploy\frontend`（不是 `src`）
2. 确认 `manifest.json` 里 `appid` = `__UNI__510B38E`（已改好）
3. 菜单 **发行 → 原生App-云打包**
4. Android 页签：
   - 包名：`uno.imessage.app`（已写进 `manifest.json` 的 `packagename`）
   - 证书：选 **「使用DCloud云端证书」**
   - 勾选 **打正式包**
5. 点打包，3–10 分钟，产物在 `unpackage\release\apk\`

打完后**必须核对**签名，确认和后台登记的一致：

```powershell
cd "_deploy\tools\jdk8u504-b01\bin"
.\keytool.exe -printcert -jarfile "你的.apk"
```

输出的 SHA1 必须是 `25:5D:71:...`。

### 3.1 命令行云打包（不用点 GUI）

HBuilderX 的 `cli.exe` 直接支持云打包（[官方文档](https://hx.dcloud.net.cn/cli/pack.md)）：

```powershell
$hx = "C:\Program Files (x86)\HBuilder X"

# 1) 启动 HBuilderX（必须，cli 依赖已运行的实例）
& "$hx\cli.exe" open

# 2) 导入项目（路径最好是纯英文，中文路径容易出问题）
& "$hx\cli.exe" project open --path "C:\im-local\hx-frontend"
& "$hx\cli.exe" project list          # 确认已导入

# 3) 云打包 —— androidpacktype 3 = 使用云端证书
& "$hx\cli.exe" pack --project "C:\im-local\hx-frontend" `
    --platform android `
    --android.packagename uno.imessage.app `
    --android.androidpacktype 3

# 4) 查状态
& "$hx\cli.exe" pack status --project "C:\im-local\hx-frontend"
```

**`--android.androidpacktype` 取值：**

| 值 | 含义 |
|---|---|
| `0` | 使用自有证书（要配合 certalias / certfile / certpassword / storepassword） |
| `1` | 使用公共证书（DCloud 测试证书，**不能上架**） |
| `2` | 使用 DCloud 老版证书 |
| **`3`** | **使用云端证书** ← 我们用这个（别名 `__uni__510b38e`） |

用自有证书的话：

```powershell
& "$hx\cli.exe" pack --project "C:\im-local\hx-frontend" `
    --platform android `
    --android.packagename uno.imessage.app `
    --android.androidpacktype 0 `
    --android.certalias "__uni__510b38e" `
    --android.certfile "C:\im-local\app-cert.keystore" `
    --android.certpassword "<REDACTED_KEYSTORE_PW>" `
    --android.storepassword "<REDACTED_KEYSTORE_PW>"
```

> 首次执行可能提示「正在下载依赖插件，请稍后重试」，等 1–2 分钟重试即可。
> 打包成功后传统打包会直接输出 APK 下载地址（临时链接，只能下载 5 次）。

## 4. 离线打包（Android Studio 路线）

### 4.1 AndroidManifest.xml

`<application>` 节点内加：

```xml
<meta-data
    android:name="dcloud_appkey"
    android:value="<REDACTED_DCLOUD_APPKEY>" />
```

### 4.2 build.gradle 签名配置

```gradle
signingConfigs {
    config {
        keyAlias '__uni__510b38e'
        keyPassword '<REDACTED_KEYSTORE_PW>'
        storeFile file('dcloud-__UNI__510B38E.keystore')
        storePassword '<REDACTED_KEYSTORE_PW>'
        v1SigningEnabled true
        v2SigningEnabled true
    }
}
buildTypes {
    release {
        signingConfig signingConfigs.config
    }
}
```

> 坑：`signingConfigs` 必须挂到 `buildTypes` 里才生效。
> 另外离线工程的 `assets/data/dcloud_control.xml` 里 appid 必须是 `__UNI__510B38E`。

### 4.3 三方必须一致

```
appid     = __UNI__510B38E
包名       = uno.imessage.app
签名SHA1  = 25:5D:71:27:5F:77:53:FC:04:96:65:45:1B:F1:9E:1A:2B:5F:F7:F8
```

## 7. 云打包前还必须处理的坑

### 7.1 原生插件 TUICallingUniPlugin —— ✅ 已处理

位置：`src\nativeplugins\TUICallingUniPlugin-TUICallingModule\`（腾讯 TRTC 音视频通话）

`manifest.json` 里原本标着 `"isCloud": false`（**本地插件**）——本地插件**无法用于云打包**，会直接失败。

**已处理**：`nativePlugins` 段已从 `manifest.json` 移除，云打包不再被卡住。
原文件备份在 `src\manifest.json.bak-含TRTC插件`，将来需要恢复就把那段贴回去。

代价：App 内没有音视频通话（点通话按钮无反应）。插件文件本身**没有删**，仍留在 `nativeplugins\` 目录里，将来走**离线打包**（Android Studio）时可以直接用。

> 小提示：代码里 7 处 `uni.requireNativePlugin('TUICallingUniPlugin-TUICallingModule')` 仍在。
> 插件缺失时它返回 `undefined`，而这些调用都包在 `/trtc/getSign` 的 `success` 回调里 ——
> 后端没配 TRTC 时该接口不会成功，所以不会崩。**正式上线前如果想彻底干净**，
> 可以给这几处加上空实现兜底，或直接删掉 TRTC 相关代码块。

### 7.2 高德 / 腾讯地图 key 都是作者的

| 位置 | 现值 | 说明 |

| `sdkConfigs.geolocation.amap.appkey_android/ios` | `81cc6c72aeb6a1946510cc1e9f87ee80` | 作者的 |
| `sdkConfigs.maps.amap.appkey_ios` | 同上 | 作者的 |

**高德 key 绑定「包名 + SHA1」**，所以必须换成自己的，否则打包后定位/地图不可用。

修复步骤：

1. 去 [lbs.amap.com](https://lbs.amap.com) 注册登录
2. 控制台 → 应用管理 → 创建新应用 → 添加 Key
3. 服务平台选 **Android 平台**，填：

   - 包名：`uno.imessage.app`
4. 拿到的 Key 替换 `manifest.json` 里 3 处 `appkey_android`

> 你之前遇到的「定位不可使用」在 H5 版是 HTTPS 问题（已修）。
> 在**打包版**里就是这个问题 —— 高德 key 校验不过。
